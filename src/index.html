Featured Capstone Case Study Project Manager & Lead Programmer 5 Role-Based Apps

Android-Based Smartphone Barangay Service Portal with Appointment Management for Improved Communication

Client: Barangay II Población, Pontevedra, Negros Occidental · Prototyped in Google Stitch · Built with Flutter (Dart) & Cloud Firestore

Problem & Engineering Scope

Manual walk-in logs and fragmented messaging slow down emergency coordination and clinic scheduling across Barangay II Población, Pontevedra, Negros Occidental. This capstone links residents, barangay officials, Chief Tanod dispatchers, patrolling Tanods, and Barangay Health Workers across five dedicated Android apps backed by live Cloud Firestore sync, GPS tracking, and rule-based report validation.

Authorship boundary: Serving as Project Manager and Lead Programmer, Jay-R authored the application source code across every Flutter role client and Firebase backend rules independently (excluding team academic manuscripts). Google Stitch was used strictly for initial screen layouts; every production widget, Cloud Firestore repository, FCM trigger flow, GPS service, and validation rule was written directly in code.

Five Role-Based Mobile Applications

Scoped via Firebase Authentication (RBAC)

01 · Resident Mobile App

Registered Residents

Supports account onboarding and barangay selection, one-tap Emergency SOS and photo + GPS incident submission, healthcare appointment booking, medicine availability lookup, announcements/community forum, and live tracking (Pending → Assigned → En Route → Resolved).

02 · Barangay Admin App

Captain & Officials

Provides an executive analytics dashboard, role/account provisioning for Healthcare Admin and Tanod Admin accounts plus resident verification, official disaster/event alerts, community forum moderation, and system audit logs.

03 · Tanod Admin (Security Administrator) App

Chief Tanod Command

Surfaces live Emergency SOS and incident feeds paired with an interactive Live Map Command Center plotting active incidents alongside patrolling units, rule-assisted fake-report verification, rapid unit dispatch, and case resolution workflows.

04 · Tanod / Field Patroller App

On-Duty Responders

Includes an operational duty toggle (Available / Busy / Responding / Offline), push dispatch alerts with Google Maps turn-by-turn routing to resident GPS pins, background location streaming for ETA, and status updates (Assigned → En Route → Arrived → Investigating → Resolved).

05 · Healthcare Admin App

Barangay Health Workers & Midwives

Manages clinic appointment approval, rescheduling, and cancellation; tracks medicine and medical supply inventory with expiration monitoring; publishes immunization, maternal care, and medical-mission advisories; and exports patient consultation and request logs.

System Architecture

Google Stitch → 5 Flutter Apps → Cloud Firestore & FCM

Engineering Trade-Offs & Technical Proof

Connecting five distinct municipal roles on one backend demands strict authorization boundaries in Cloud Firestore, automated triage checks before responder dispatch, and resilient live tracking under mobile field conditions.

RBAC via Firebase Auth

Enforces role claims (resident, tanod, healthcare_admin, barangay_admin) directly in Cloud Firestore security rules.

Rule-Based Validation

Evaluates coordinate bounds, photo attachment links in Firebase Cloud Storage, and duplicate bursts to help Chief Tanods filter false alarms.

Firestore + FCM Streams

Maps QuerySnapshot streams into typed Dart models for live GPS ETAs while FCM wakes patrolling units immediately.

firestore.rules Scrubbed Cloud Firestore Role-Based Security Rules
Representative scrubbed Cloud Firestore RBAC rule excerpt (project IDs omitted) 
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    function hasRole(role) {
      return request.auth != null && request.auth.token.role == role;
    }

    match /incidents/{incidentId} {
      allow read: if request.auth != null && (
        resource.data.residentId == request.auth.uid ||
        hasRole('tanod_admin') ||
        hasRole('tanod') ||
        hasRole('barangay_admin')
      );
      allow create: if hasRole('resident')
        && request.resource.data.residentId == request.auth.uid
        && request.resource.data.status == 'Pending'
        && request.resource.data.lat is number
        && request.resource.data.lng is number;
      allow update: if hasRole('tanod_admin') || hasRole('tanod');
    }

    match /appointments/{apptId} {
      allow read: if request.auth != null && (
        resource.data.residentId == request.auth.uid ||
        hasRole('healthcare_admin') ||
        hasRole('barangay_admin')
      );
      allow create: if hasRole('resident')
        && request.resource.data.residentId == request.auth.uid
        && request.resource.data.status == 'Pending';
      allow update: if hasRole('healthcare_admin');
    }
  }
}
incident_repository.dart Representative Flutter / Dart Cloud Firestore Stream Snippet
Representative Dart repository streaming Cloud Firestore incident updates 
Stream<List<IncidentReport>> watchActiveIncidents(FirebaseFirestore firestore) {
  return firestore
      .collection('incidents')
      .where('status', whereIn: ['Pending', 'Assigned', 'En Route', 'Arrived', 'Investigating'])
      .orderBy('createdAt', descending: true)
      .snapshots()
      .map((QuerySnapshot<Map<String, dynamic>> snap) => snap.docs
          .map((doc) => IncidentReport.fromFirestore(doc.id, doc.data()))
          .toList());
}
